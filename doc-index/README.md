# 文档索引 · Doc Index

为工作区文档提供 **BM25 中文全文检索**。纯本地、零依赖、无 embedding、不联网、无 API 成本。

治理范式移植自 [DSH-SEP](https://github.com/Lance-QwQ/DSH-SEP) 的 RAG 子系统。

## 能力

| 工具 | 作用 |
|---|---|
| `doc_index` | 建立/刷新索引；增量（未变文件复用分块）；可传 `paths` 只索引指定文件 |
| `doc_search` | BM25 检索，返回文件路径 + 字符偏移 + 片段原文 |
| `doc_status` | 索引代次、源文件数、分块数、陈旧文件清单 |
| `doc_clear` | 清空索引 |

## 支持的文件类型

`.md` `.markdown` `.txt` `.json` `.csv` `.log` `.yaml` `.yml`

## 中文检索怎么做的

移植自 DSH-SEP 的 `vendor/bm25.js`（MIT，上游 `imkelt/DSH-RAG`）：

```
拉丁词    →  \p{Letter}\p{Number}+ 切分
中文      →  单字 + bigram 切分（无需词典）
混合查询  →  再叠加 Intl.Segmenter 词切分
```

**在 SEP 原版基础上增加两处长文档改进**（原版没有）：

1. **单字降权**：单个汉字在长文档里几乎必然命中，权重降到 0.15
2. **强 token 判据**：只有孤立单字命中的文档直接丢弃

> 这里刻意**不用绝对分数阈值**。语料只有 1 篇时 BM25 的 idf 上限仅约 0.29，任何绝对阈值都会让检索永远为空——这是实测踩到的坑。

## 陈旧检测是硬约束

索引为每个源文件记录 SHA-256，检索前逐个校验：

```
文件内容变了  →  DOC_INDEX_STALE
文件被删除了  →  DOC_INDEX_STALE
```

**宁可不回答，也不用过期索引回答。** 收到该错误时重新调 `doc_index`。

## 来源可定位

每个命中带 `path` + `start` + `end`：

```json
{ "path": "docs/api.md", "start": 128, "end": 260, "score": 2.41, "text": "…" }
```

需要更多上下文时读原文件那一段，不要凭片段推测全文。

## 边界

| 项 | 上限 |
|---|---|
| 单文件 | 1 MB |
| 语料总量 | 16 MB |
| 分块总数 | 4000 |
| 单次返回 | 10 条 |
| 上下文 | 6000 字符 |

## 权限

| 权限 | 用途 |
|---|---|
| `agent.tool.register` | 注册 4 个工具 |
| `agent.prompt.inject` | 注入使用规范技能 |
| `fs.read` | 读取工作区文本文件（scope `**`） |


索引文件由插件用 Node 原生 `fs` 写入**自己的**数据目录（`getDataPath()`）。
这不改变权限承诺：插件对工作区始终只读，唯一的写入落在自己的沙箱内。

> 走宿主网关 `pi.fs` 写数据目录是**行不通的**：该网关的作用域由 manifest 的
> `fs.read`（`root: workspace`）限定，对工作区之外的路径写入会被直接拒绝。
> v0.2.1 正是踩了这个坑 —— 读写两端都走 `pi.fs`，于是索引永远落不了盘，
> `doc_index` 恒返回 `DOC_INDEX_WRITE_FAILED`。v0.2.2 起改用 `node:fs` + 原子写。

## 测试

```bash
node test-doc-index.cjs
```

55 项断言，覆盖：索引建立、**索引真实落盘**、增量复用、中文/英文/混合检索、来源定位、上下文预算、SHA-256 陈旧检测、文件删除检测、指定路径索引、清空、BM25 引擎单元测试、项目隔离、无工作区降级、卸载清理。

测试用**真实的**临时数据目录（不是内存 fs），并模拟「网关不允许写数据目录」这一权限约束 ——
旧版测试把 `pi.fs` 的读写都实现成对象存取，把这条约束一起假掉了，53 项全绿却掩盖了索引落不了盘的事实。
