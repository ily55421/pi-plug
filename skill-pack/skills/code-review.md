# 代码审查（移植自 MiniMax Code /review 命令行为）

## 流程

1. **收集范围**：默认审查当前工作区未提交改动（`git status` + `git diff`，必要时含 staged）；用户指定文件/commit 范围则以其为准。
2. **上下文预算**：改动很大时优先读 diff 与其直接依赖；只对可疑点回读完整文件，避免全量读大文件。
3. **审查维度**（按此顺序排查）：
   - 正确性：边界条件、空值、错误处理、并发/时序
   - 安全：注入、路径穿越、凭据泄漏、不安全反序列化
   - 回归：契约变更（参数/返回值/事件）与调用方是否同步
   - 性能：明显 N+1、重复 IO、无界集合
   - 可维护性：命名、重复代码、死代码
4. **每条问题固定格式**：
   - `[严重度] 位置`（file:line）
   - 问题描述（一句话）
   - 建议修法（具体到代码方向）

## 输出契约

- 开头一行总结：改动意图推断 + 总体评价。
- 问题按 `Blocker / Major / Minor / Nit` 分组；无问题的组省略。
- 结尾给"建议的验证动作"（跑哪些测试/命令）。
- 不夸奖凑数；没有问题就直说并说明检查过什么。

## 边界

- 只读不改代码，除非用户明确要求顺带修复。
- 区分"事实问题"与"风格偏好"，后者归 Nit 并注明。
