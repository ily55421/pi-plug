# 深度研究（移植自 MiniMax Code deep-research 技能方法论）

## 流程

1. **澄清问题**：确认研究对象、交付格式（简报/长文/对比表/决策建议）与读者。
2. **拆解**：把主题拆成 3~6 个必须回答的子问题，先列大纲给用户确认（简短任务可跳过确认）。
3. **多轮检索**：
   - 每个子问题至少一次独立检索；不同关键词/角度各查一次。
   - 优先一手来源（官方文档、源码、原始论文/公告），其次二手解读。
   - 记录每条信息的来源 URL/路径，标在引用处。
4. **交叉验证**：关键数字/结论至少两个独立来源一致才采信；冲突时并列呈现并说明分歧。
5. **综合成文**：
   - 结构：结论先行（TL;DR 3~5 条）→ 各子问题分节 → 来源清单
   - 区分事实与推断；推断必须标注"推断"
   - 检索不到的内容明确写"未找到"，禁止脑补填充

## 输出契约

- 长度与用户要求的格式一致；默认 Markdown。
- 末尾附"来源"清单：每条 标题 + URL。
- 报告中如引用本仓库代码/文件，用相对路径。

## 边界

- 只用当次检索到的证据支撑结论；旧知识需标注"背景知识，未在线验证"。
- 涉及价格、版本、时间敏感数据必须给检索时间点。
