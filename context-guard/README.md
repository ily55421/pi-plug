# 续航压缩 · Context Guard

参考 Save Xingchi 100 的设计理念：接近请求轮次限制时提前整理上下文，用独立模型生成摘要，普通请求保持原主模型。界面采用深色卡片、模型规则与当前会话状态分栏，也支持跟随宿主浅色主题及中英文。

> **当前状态：能力预览版。当前 PI-Desktop 普通桌面会话的插件接口不足以完成定向原生压缩。此版本可配置规则、诊断能力，包含完整原生 SDK 契约的摘要适配及模拟契约测试，但不能宣称已在当前普通会话中实现自动专用模型压缩。**

## 已实现

- 本地配置页：启用开关、主模型、主模型 API 协议、压缩专用模型、2–98 轮阈值（默认 90）。模型目录来自宿主，无内置虚构模型。
- 默认关闭。当前供应商 ID、协议和完整模型 ID 必须区分大小写且精确匹配。
- 能力检测。桌面兼容层缺少完整接口时显示“不支持”，不发摘要请求，不触发压缩，不切换主模型。
- 完整原生 SDK 契约适配：从当前分支恢复检查点后的已完成 assistant 请求数；在用户任务结束后检查阈值，通过 `ctx.compact()` 申请原生压缩；在 `session_before_compact` 中调用注册表的 `complete()` 生成摘要。
- 原生保留边界与 `tokensBefore` 原样返回；只有 `session_compact` 携带本插件对应的检查点标识时才报告专用摘要成功。
- 失败、空摘要、截断、取消、窗口不足、目标模型消失或生成期间设置改变时取消本次压缩，暂停自动重试；可以调整配置或手动 `/compact` 重试。
- 会话状态隔离，私有状态文件使用会话 ID 的 SHA-256 摘要命名，不保存用户对话、提示词、密钥或供应商原始错误。

## 当前宿主的具体限制

本次核对了本机安装版 `resources/agent-runtime`，并与本机 PI-Desktop 源码比较。两者不能混为同一版本；以下限制在安装版普通桌面会话中也存在：

1. `session_before_compact` 仅提供 `reason` / `retentionMode`，仅采纳 `{ cancel }`。不提供压缩 preparation、branch、signal，也不采纳自定义摘要结果。
2. 桌面 `ctx.modelRegistry` 不提供独立 `complete()`；公开模型目录也不是所有已配置模型的带认证执行注册表。
3. 桌面 `sessionManager.getBranch()` / `getEntries()` 返回空数组，不能恢复真实计数。
4. 桌面 `ctx.compact()` 只设置 pending 标志，不接受摘要模型，不保证下一条普通请求之前完成压缩。
5. 不能通过 `before_provider_request` 改写摘要请求：宿主生成摘要不经过这个钩子。

因此插件不会使用“先修改会话主模型 → 压缩 → 修改回来”的非原子方案。那会给普通请求误用临时模型留下窗口。

**要在当前普通桌面会话完整落地，必须由宿主新增一次性定向压缩能力，并提供真实分支/计数快照与可核验结果。** 原生 Pi 会话使用另一套 SDK，但 PI-Desktop 不会自动把普通插件扩展当作 Native Pi 的资源加载；本插件不擅自修改用户的原生扩展路径或宿主程序。原生适配仅做契约测试，尚无真实供应商端到端验证。

## 安装与打开

使用 `dist/local.context-guard-0.1.0.piplug`，在 PI-Desktop 插件页导入。或从插件页加载本目录作为开发插件，审阅 `ui.panel`、`models.list`、`agent.extension` 权限。命令面板搜索 **续航压缩：配置与状态**。

首次脚手架加载曾遇到工作区 `type: module` 与模板 CommonJS 入口的冲突；现已改为 `main.cjs`。由于原脚手架只授予 `ui.panel`，新增权限需要在插件页重新审阅；文件热重载不会自动扩大授权。打包成功不等于已安装、已授权或已在会话运行。

启用开关表示保存的规则状态；当前会话是否真正可执行，以“当前会话”中的能力状态为准。现有已运行会话可能需要新建会话才会加载扩展。即便完成安装，当前普通桌面接口的功能限制仍然存在。

## 测试

在仓库根目录运行，临时文件仅使用已有的 `PI_SCRATCH_DIR`：

```powershell
node --test .\context-guard\tests\*.test.mjs
```

测试覆盖精确匹配、默认关闭、当前桌面契约拒绝、原生计数恢复、摘要边界、主模型保持、取消、失败、配置变更、窗口不足、重试暂停与会话隔离。模型调用为测试替身，测试不联网、不消耗真实模型额度。

## 计数及摘要边界

计数是上次检查点之后成功完成的 assistant 请求；不等于用户消息数，不包含失败请求、网络重试或工具结果。在用户任务结束后才检查阈值，不能保证一个很长的工具循环绝不超过 100 次调用。阈值 90 只是预留余量，不是供应商上限的硬保证。

摘要传递此前摘要、本次历史和分割轮次的前缀；图片只保留附件提示，不发送图片编码；思考块不复制。摘要模型窗口预检以 UTF-8 字节数做保守上界，宁可拒绝也不静默截掉用户内容。后续仍依赖宿主保留原始记录与原生检查点语义。

## 文件

- `config.cjs`：配置白名单、校验与三元组匹配。
- `main.cjs`：设置与模型目录桥接、私有运行状态读取。
- `extension/core.mjs`：能力检测、计数与原生 SDK 摘要适配。
- `extension/index.mjs`：扩展入口、私有设置与原子状态写入。
- `renderer/`：配置和状态页。
- `tests/`：配置、宿主桥接与扩展事件契约测试。

不访问工作区，不启动进程，不创建本地代理，不读取宿主凭据，不更改用户的模型配置，不修改 PI-Desktop 安装文件。
